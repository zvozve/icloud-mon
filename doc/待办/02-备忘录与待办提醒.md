# 02 备忘录与待办提醒（旁路打通后新增）

前提：01 的 Qt 侧接入**已完成**（2026-10-13，commit bfe5827）—— 旁路已能稳定供数，
界面已能消费 payload。这些功能全部走 iCloud 网页后端，与官方客户端无关 —— 客户端卡死不
影响它们。

**当前状态：一行都还没动。** 01 做的是「把已有功能搬到 Python」（数据源搬家），
没有新增任何取数能力。下面 02 的每一条都是新增能力，第一道门是**认证层** ——
过不了认证，待办/备忘录一条都读不到。

原则：**只读优先**。读取先上线，写入单独成条并标风险，验证过再放开。

## 认证层（所有功能的前置）

> ★ 2026-10-13 更新：认证路径可能**整块外包给浏览器** —— 见
> `doc/认证与取数路径评估.md`。浏览器（CDP 或内嵌 WebEngine）过登录，
> 我们只取 `X-APPLE-WEBAUTH-TOKEN` 系列凭据，SRP-6a/GSA/2FA **一条都不用写**。
> 先跑 `sidecar/probe_browser_auth.py` 探针验证，再决定要不要内嵌 107 MB 的 WebEngine。
> 下面第 1、2 条在该路线走通后作废。

[ ] 引入 pyicloud（timlaing fork，覆盖 Drive/Notes/Find My/Reminders）—— 若走浏览器认证，pyicloud 只当**取数客户端**，不负责登录

[ ] 登录链路：SRP-6a + GSA + 2FA 弹窗；2FA 输入在 Qt 侧给交互入口（不能只靠命令行）

[ ] 凭据存储：keyring 或加密文件，禁止明文落盘；确认与现有 QSettings 不混放

[ ] 会话过期处理：token 失效时返回可识别错误码，界面提示"需要重新登录"而非静默失败

[ ] 轮询策略：备忘录/待办不低于 5 分钟一次；避免高频调用触发 Apple 风控

[ ] 测试账号约定：用副 Apple ID 验证，不用主力号（避免风控锁号）

## 备忘录

[ ] 读取：列表 + 文件夹 + 详情 + 本地搜索（CloudKit Web 读路径）

[ ] 渲染：标题/正文/更新时间；图片与附件先只显示占位，不做内联渲染

[ ] 快速便签（置顶便签）单独归类显示，本质是带特定属性的备忘录记录

[ ] 写入（新建/编辑）：走 CloudKit record 写路径，冲突处理（同一条被多端改动）先只做"最后写入覆盖 + 提示"

[ ] ADP 检测：账号开启高级数据保护时明确降级提示"该数据端到端加密，无法读取"，不做无意义重试

## 待办事项（Reminders）

[ ] 完成/勾选：写入路径同备忘录，风险同上，放在只读之后

## 风险与边界

法律与条款：使用非官方客户端访问违反 Apple 服务条款，存在账号风控风险；仅用于本机自查，不公开分发凭据相关实现。

数据边界：端到端加密的数据（钥匙串密码、开启 ADP 后的受保护项）一律不在范围内。
