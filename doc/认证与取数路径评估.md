> ## ★★ 修正（2026-10-13 当天，依据 pyicloud 官方文档核实）
>
> **本文结论二（浏览器过认证、取 token 喂协议）作废 —— 不需要浏览器。**
>
> 上一轮推荐它，是因为我当时以为「SRP-6a + GSA + 2FA 得自己写，交给浏览器最省」。
> 查证 pyicloud（timlaing fork）官方文档后发现：**这些它全都已经实现好了**，

> 结论一（浏览器不该当 UI）与结论三（取数走协议不抓 DOM）**不变，且更成立** ——
> 既然协议路径有现成库，抓 DOM 就更没有理由了。

**新结论：浏览器不用接，也别接。**

## 原始评估（保留备查，其"认证交给浏览器"的建议已作废）

一句话结论：**能。而且它能把整个「认证层」删掉** —— 但方向要掰正：
**浏览器只该用来过登录，不该用来抓数据。**

---

## 一、这句话里的两个岔路

「接入浏览器模块，登录然后重绘 UI」= 三件独立的事，可以拆开各自选：

| 环节 | 谁来做 | 说明 |
|---|---|---|
| 登录（SRP-6a + GSA + 2FA） | **浏览器** | 交给 Apple 自己的页面，我们零代码 |
| 取数（备忘录 / 待办） | **协议**（CloudKit Web API） | 契约稳定、有文档；**不要抓 DOM** |
| 画界面 | **QML 自绘**（保持现状） | 现有监控语义、托盘、通知都还在 |

「重绘 UI」有两种理解，代价差一个数量级：

- **读法一**：浏览器只当管道，数据抓出来喂**我们自己的** QML → 推荐
- **读法二**：浏览器直接当界面，注入 CSS 把 iCloud 页面**换皮** → 等于做个 iCloud 专用浏览器，
  且 Apple 的 DOM class 是哈希的（`.note-title-8f3a`），每次发布都可能断，我们永远在追

## 四、推荐：路线 D —— 浏览器过认证，协议取数，QML 自绘

**为什么不是「浏览器全包」**：认证是这个项目里最脏最重的部分 ——
SRP-6a 握手、GSA 二次认证、2FA 弹窗、风控锁号、ADP 端到端加密降级。
这些交给 Apple 自己的登录页 = **白送**，一行都不用写。

而取数恰好相反：CloudKit Web Services 是**公开文档化**的 REST 接口，
契约比 DOM 稳得多。用 DOM 抓数据是拿最脆弱的方式去做最需要稳定的部分。

**关键接点**：浏览器登录后，我们能读到这几条 cookie / 会话值 ——

```
X-APPLE-WEBAUTH-TOKEN      （双因素会话票据，pyicloud 正是要它）
X-APPLE-DS-WEB-SESSION-TOKEN
X-APPLE-WEBAUTH-USER       （DSID）
```

拿到它们 = 拿到了 pyicloud 需要的**全部凭据**。于是
**SRP-6a + GSA + 2FA 全部不用实现**，直接进入协议取数。

> 一句话：**浏览器负责「证明你是你」，协议负责「取数据」。**

## 五、第一刀（可逆、零体积、不碰主程序）

做一个独立探针 `sidecar/probe_browser_auth.py`（不动现有一行代码）：

1. 起一个**独立 user-data-dir** 的 Edge：`--remote-debugging-port=9222`（只绑 127.0.0.1）
2. 弹出窗口 → 用户手动登录 iCloud（含 2FA）→ 登录态留在该 profile 目录
3. Python 侧用 websocket 走 CDP 读 cookie，并试调一次 CloudKit Web API 列提醒事项清单
4. 用完关掉这只看门狗进程，端口回收

**验证三件事（决定后面要不要付 107 MB）**：

| # | 待验证 | 通了说明 |
|---|---|---|
| 1 | 能否拿到 `X-APPLE-WEBAUTH-TOKEN` 系列 | 认证层彻底外包，02 的 6 条认证待办作废大半 |
| 2 | 用这些 token 能否直接调 CloudKit Web API 列出「提醒事项」清单 | **不需要内嵌 WebEngine，省 107 MB** |
| 3 | 登录态能持久多久（profile 目录复用） | 决定「多久要重登一次」的产品体验 |

**分支**：若第 2 条不通（token 不够、还需页面内 JS 会话）→ 才付 107 MB 内嵌
WebEngine，用 `runJavaScript` 取页面内的会话与数据。**先验证再掏钱，不预先打包。**

## 六、风险

| 风险 | 处置 |
|---|---|
| DOM 抓取是脆弱契约 | 只在协议路线走不通时当兜底，且把选择器集中在一个文件里 |
| 多一个外部浏览器进程要管 | 只绑 127.0.0.1、用完即关、parent 死了随 stdin/管道一并退出 |
| CDP 端口暴露 | 不监听 0.0.0.0；端口随机化；退出时确认进程已死 |
| 绿色单文件形态 | 本方案不增加打包体积；且本工具本来就依赖 iCloud 客户端 |
| ADP（高级数据保护） | 网页端也可能读不到 → 明确降级提示，不做无意义重试 |
| 风控锁号 | **用副 Apple ID 验证**，不拿主力号试 |
